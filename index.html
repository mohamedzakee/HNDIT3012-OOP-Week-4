1What is Object Oriented Programming?

OOP is a programming paradigm that uses objects to represent and manipulate data using real-world concepts.

Data is encapsulated inside objects, and each object is defined by its properties (attributes) and behaviours (methods).

OOP gives youMeaning
Modular codeSplit into separate, self-contained classes
Reusable codeOne class makes many objects
Maintainable codeChanges stay inside one class
Procedural thinking asks "what steps?". OOP asks "what things exist, what do they know, and what can they do?"
2The four main OOP concepts

Encapsulation

Bundle data and methods together; hide fields with private.

Inheritance

A child class reuses a parent class. Car is a Vehicle.

Polymorphism

One name, many forms. The same call acts differently.

Abstraction

Show what it does, hide how it does it.

Memory hook: A PIE → Abstraction, Polymorphism, Inheritance, Encapsulation. Later weeks cover each in depth.

4Anatomy of a Java class
class Vehicle {
    private int doors;        // fields = state
    private int speed;
    private String color;

    public void run() {       // method = behaviour
        System.out.println("Vehicle is running, speed is " + speed);
    }
}
PartMeaning
privateOnly code inside this class can use it
publicAny class can use it
int, StringData types (String has a capital S)
voidThe method returns nothing
Conventions: classes in PascalCase, fields and methods in camelCase. Java is case-sensitive.
5Creating and using objects
Vehicle car = new Vehicle();   // create

Fields never set get defaults: int → 0, double → 0.0, boolean → false, objects → null. That's why the slide program prints speed is 0.

6Constructors and this
public Vehicle(int doors, int speed, String color) {
    this.doors = doors;   // this.doors = field, doors = parameter
    this.speed = speed;
    this.color = color;
}
Vehicle car = new Vehicle(5, 180, "white");

A constructor has the exact class name and no return type (not even void). It runs automatically on new.

If you write none, Java gives a default constructor. Once you write your own, the default disappears.

7Getters, setters and encapsulation
public int getSpeed() { return speed; }

public void setSpeed(int speed) {
    if (speed >= 0) this.speed = speed;   // reject bad values
}

Private fields + public getters/setters = encapsulation. A setter can refuse bad data like -500; a public field could not.

Try it in the Object Factory: set a negative speed and watch the setter protect the object.
